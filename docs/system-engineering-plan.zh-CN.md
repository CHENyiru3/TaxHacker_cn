# TaxHacker_cn 前后端工程合理化与部署总规划（V2）

> 目标：在保持默认中文体验的前提下，将当前 Next.js 单体演进为“边界清晰、可扩展、可部署、可持续交付”的工程体系。

## 1. 当前现状（已完成）

- 默认中文 + 英文切换基础能力已上线。
- 多租户基础模型已具备：`organizations` / `memberships` / `audit_logs`。
- 导入中台基础已具备：`data_sources` / `import_jobs`。
- 导入任务可视化页面已具备（总览指标 + 列表）。

## 2. 关键工程问题（必须继续补齐）

1. **应用服务层不完整**：部分页面、Server Action 仍直接编排业务流程。
2. **入口不统一**：API 与 Server Action 都在执行业务，易出现权限与口径漂移。
3. **任务体系待调度化**：已具备 worker 处理端点与 pending 消费逻辑，仍缺正式调度器与并发控制。
4. **规则与指标体系未落地**：还未形成可审计、可版本化的咨询核心资产。
5. **交付链路不闭环**：报告版本化、分析师审核流尚未形成体系。

## 3. 目标工程架构（建议）

### 3.1 分层边界

- **表现层（UI）**：`app/` + `components/`
  - 只负责展示与用户交互。
- **接口层（API / Server Action）**：`app/api/` + `app/**/actions.tsx`
  - 只做参数验证、鉴权、调用 service。
- **应用服务层（Use Case）**：`services/`
  - 编排业务流程：导入、任务状态、规则执行、报告生成。
- **领域访问层（Model/Repository）**：`models/`
  - 只包含数据库访问与基础查询能力。
- **基础设施层**：`lib/`
  - 鉴权、租户上下文、i18n、队列客户端、日志、配置。

### 3.2 访问规则（强约束）

- UI 不得直接访问 Prisma。
- API 与 Server Action 不得直接写复杂业务流程。
- 复杂流程必须进入 `services/`。
- `models/` 禁止依赖 UI 代码。

## 4. 后续系统还需要什么（能力清单）

### 4.1 数据与任务中台

- `job_runs`：一次任务多次执行记录。
- `job_artifacts`：中间文件/错误报告/导入明细。
- 导入失败分类与重试策略。
- 异步 worker（Python）执行 OCR、清洗、批处理。

### 4.2 咨询核心能力

- 指标引擎：指标口径版本化。
- 规则引擎：规则 DSL + 命中证据。
- 证据层：`evidences` 统一回链。
- 报告中心：`reports` / `report_versions`。
- 智能体会话层：`chat_sessions` / `chat_messages`（已起步，待工具化）。

### 4.3 分析师工作台

- 案件流转（待补资料/待复核/已交付）。
- 报告审阅与批注。
- 案例沉淀与复用。

## 5. 部署规划（完整）

### 5.1 环境分层

- `dev`：本地开发（单机 Postgres + Next.js）
- `staging`：预发布验收（与生产同构）
- `prod`：生产（高可用）

### 5.2 服务拓扑（建议）

- `web`：Next.js（Node）
- `db`：PostgreSQL
- `redis`：队列与缓存（后续启用）
- `worker-py`：Python 任务执行服务
- `object-storage`：MinIO/S3（票据、工件）

### 5.3 发布流程（建议）

1. Push / PR 到 `work` 触发验收。
2. 通过后合并并发版到 `staging`。
3. 冒烟 + 回归通过后发布 `prod`。
4. 执行 DB migration（先备份后迁移）。

### 5.4 观测与运维

- 日志：结构化日志 + traceId。
- 指标：导入成功率、失败率、任务时延、报告时延。
- 告警：导入失败异常、规则执行异常、模型调用异常。

## 6. 迭代路线（执行顺序）

### 阶段 A（工程稳定）

- 全量导入流程收敛到 `services/`。
- 新增任务异步化基础（队列与 worker 占位）。
- 引入统一 DTO / schema 验证策略。

### 阶段 B（咨询可交付）

- 指标引擎 + 10 条高频规则 + 证据回链。
- 报告模板化导出。

### 阶段 C（规模化）

- 案件工作台 + 报告版本化。
- ERP 增量同步。

## 7. AI 协作开发规范（与后续功能强相关）

- 新增功能必须明确：目标文件、目标片段、验收标准。
- 所有 AI 代码修改请求都应使用统一结构（见 `docs/ai-targeted-modification-guide.zh-CN.md`）。
- 复杂变更优先“先出计划再改代码”，防止跨层乱改。
