# TaxHacker_cn 财税咨询智能体项目规划（V1）

> 目标：基于现有 TaxHacker_cn（Next.js + Prisma + PostgreSQL）底座，建设“客户自助 + 分析师交付”的财税咨询智能体平台。默认技术语言为 **TypeScript（应用层）** 与 **Python（数据与AI任务层）**。

## 1. 项目定位与范围

### 1.1 定位

- 面向中小企业客户：提供可解释、可追溯的财税问答与体检报告。
- 面向内部分析师：提供案件工作台、规则审阅、报告协作与知识沉淀。

### 1.2 本期范围（优先级）

1. 前端默认中文化（保留英文界面切换能力）。
2. 多租户与权限体系（组织/成员/角色/审计）。
3. 数据接入与规范化（先文件导入，后ERP API）。
4. 指标计算与规则引擎（可审计、可版本化）。
5. 对话智能体（工具调用 + 证据引用 + 人审兜底）。

---

## 2. 总体架构（TypeScript + Python）

## 2.1 前后端应用层（TypeScript）

- 框架：Next.js（App Router）
- ORM：Prisma
- DB：PostgreSQL
- 能力：
  - 多租户访问控制
  - UI/工作台
  - API 网关与鉴权
  - 规则执行入口与报告交付

## 2.2 数据与AI任务层（Python）

- 运行形式：独立 worker 服务（容器化）
- 建议技术栈：
  - `pandas`：账务/流水/发票数据清洗
  - `pydantic`：规范化 schema 校验
  - `fastapi`（可选）：内部任务 API
  - `celery/redis` 或 `rq`：异步任务
- 能力：
  - OCR/文档结构化预处理
  - 数据质量校验与映射
  - 批量指标预计算
  - 模型评测回放

## 2.3 模型网关层

- 对外统一 OpenAI-compatible 接口，便于切换模型。
- 支持国内模型（示例：百炼、DeepSeek）与海外模型。
- 策略：
  - 默认脱敏后发送
  - 高风险场景强制人工复核
  - 输出必须带 evidence 引用

## 3. 功能分层设计

## 3.1 客户端（自助）

- 数据上传中心：CSV/Excel/PDF
- 财税看板：收入、成本、税负、波动风险
- 智能问答：口径解释 + 证据引用
- 报告中心：月度/季度体检报告下载

## 3.2 分析师端（交付）

- 客户与授权管理
- 导入任务监控与失败重试
- 规则命中审阅（风险等级、建议动作）
- 报告编辑器（AI草稿 + 人工修订）
- 案件流转（待补资料/待复核/已交付）

## 3.3 数据中台

- Canonical Model（统一财税数据模型）
- 指标定义与口径版本化
- 规则 DSL（版本、启停、适用范围）
- 证据索引（单据、分录、期间、来源）

## 5. 安全与合规基线

1. 租户隔离：每次查询必须带 `org_id` 过滤，关键接口增加二次校验。
2. 数据安全：敏感字段加密、对象存储加密、下载水印与审计。
3. 模型安全：Prompt Injection 防护、工具白名单、最小数据发送。
4. 审计追溯：每条报告建议可回链证据、操作者与版本。
5. 交付兜底：高风险结论需分析师确认后才能对客户展示。

---

## 6. 前端中文化规范

1. 默认语言：`zh-CN`。
2. 保留英文接口：提供 `en` 语言切换能力，不破坏现有英文文案映射。
3. 文案管理：统一放入 `lib/i18n.ts` 或后续拆分字典模块。
4. 翻译原则：
   - 面向客户文案：通俗、解释型。
   - 面向分析师文案：专业、口径明确。
5. 验收标准：
   - 主导航、设置页、关键按钮默认中文。
   - 语言切换后同页面即时生效。

- 默认开发语言：
  - TypeScript：Web/API/服务端业务逻辑
  - Python：数据处理与AI任务
- 代码质量：ESLint + TypeScript strict + Python Ruff/Mypy
- 交付流程：
  - 分支开发 → PR 模板审查 → 自动化检查 → 合并
- 文档要求：
  - 每个模块附“数据口径说明 + 风险边界 + 回滚方案”

---

## 9. 验收指标（建议）

1. 导入成功率 ≥ 98%（模板内数据）
2. 核心规则命中准确率（人工抽检）≥ 90%
3. 报告生成耗时 ≤ 2 分钟
4. 客户问题首答覆盖率 ≥ 85%（其余引导补材料）
5. 关键页面中文覆盖率 100%，英文可切换可用
